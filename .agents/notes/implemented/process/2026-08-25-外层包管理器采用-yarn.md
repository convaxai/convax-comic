# 外层包管理器采用 Yarn 4

## 背景

Convax Next 同时有 Electron 产品 workspace 与只读的 DeepSeek Harness
submodule。参考桌面仓库使用 Yarn 4 + `node-modules` linker；Harness 源仓库
有自己的 pnpm workspace。外层必须能稳定生成 Electron Builder 可遍历的
物理依赖树，又不能把两个 workspace 混成一个依赖图。

## 决策

- 外层固定 `yarn@4.18.0`，采用 `nodeLinker: node-modules`。
- 默认关闭依赖构建脚本，只对白名单中的 Electron、esbuild 和 DSH 必需
  native 包设置 `dependenciesMeta.built`；架构专用 Node 包本身没有安装脚本。
- `deepseek-harness/` 保持自己的 `pnpm@11.7.0` workspace，只通过根部
  `upstream:*` 命令进入；外层运行依赖消费 npm 上精确的
  `@deepseek-ai/dsh@0.1.1-rc.2`。
- lockfile 与 submodule pin 都是升级审计输入，二者不可用范围版本替代。

## 被否方案

- **Bun workspace**：参考构建、Electron Builder 的物理依赖闭包和上游
  smoke 均以 Node/Yarn 为基线，引入 Bun 会同时扩大安装器、native 包与
  打包验证面，M1 没有收益。
- **把 submodule 加进外层 workspace**：会破坏上游自己的 pnpm 拓扑，且
  让产品运行闭包错误依赖源码 checkout。
- **PnP**：外部独立 Node、Electron Builder 与 DSH profile 的普通 Node
  resolution 都需要真实 `node_modules` 路径。

## 可证伪的验收证据

- `corepack yarn install --immutable` 可从 lockfile 重建外层依赖。
- `yarn check` headless 全绿。
- `yarn upstream:install && yarn upstream:build` 在 submodule 内以 `CI=true`
  独立执行，不让上游 postinstall 写当前 worktree 的 hook 配置。
- 打包依赖 realpath 均位于应用 `Resources`；在空 PATH、隔离 HOME/CWD 下
  不依赖全局 pnpm 或 submodule resolution 仍可启动。

## 遗留风险

M1 只打 macOS ARM64。引入 Windows x64 时必须重新审计 Yarn 的
`supportedArchitectures` 与每个 native 包的双架构闭包。
