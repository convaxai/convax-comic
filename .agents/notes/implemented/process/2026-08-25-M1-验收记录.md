# M1 验收记录

## 背景

M1 的出口不是“壳能编译”，而是 PLAN 中 Cordis 生命周期、桌面监督、控制面
鉴权、兼容 profile、真实上游与独立打包闭包的联合证据。检查必须 headless，
不能依赖开发机恰好存在的 Node、pnpm 或 submodule 构建路径。

## 决策

- 根 `yarn check` 作为快速必跑门禁；真实 npm 运行时与目录产物分别由
  `smoke:upstream`、`package:dir` 验证，避免把慢集成检查藏进单元测试。
- 上游源码只经 `upstream:*` 封装安装/构建，封装固定 `CI=true`，防止上游
  postinstall 写入当前 worktree 的 hooks。
- `dump-config` 每次从相同 bundle 生成干净基线，按 row id 检查允许差异；
  不接受只保存一份容易过期的 golden 文件。
- 图形入口保持显式 `yarn dev`。自动验收复用同一 profile、Node、DSH 与
  auth-fence 路径，但不在 CI 中打开 Electron 窗口。

## 被否方案

- **只跑单测**：无法发现 npm peer 闭包、Loader、静态前端或打包路径问题。
- **只做 GUI 手测**：不可复现，也无法精确证明 compatibility 零覆盖与
  token 失败路径。
- **把 submodule 当 smoke runtime**：会绕开真正交付的 npm/应用资源闭包。
- **记录未归一化的完整 dump**：临时目录会污染 diff，且大段快照难以审计
  哪些 row 被产品修改。

## 可证伪的验收证据

2026-08-25 在 macOS ARM64 执行并通过：

- `corepack yarn install --immutable`；外层 lockfile 无改动。
- `yarn upstream:version` 输出 pnpm `11.7.0`，随后
  `yarn upstream:install` 与完整 Host/Client/Web `yarn upstream:build`
  通过，submodule tracked status 为空。
- `yarn check` 通过 build、typecheck、12 个测试文件共 45 项测试、profile
  契约和布局门禁。
- Cordis 生命周期覆盖 consumer-before-provider、PENDING/ACTIVE、provider
  卸载后的 timer/event 清理、恢复激活和重复 provider 失败。
- 桌面单测覆盖随机 loopback 参数、独立 Node、readiness 超时/立即失败、
  `SIGKILL` 后自动重启与 token/origin 轮换、重启上限、退出回收、导航、
  preload 安全选项、日志脱敏和产品目录边界。
- 产品桌面入口显式拒绝外部 `--patch`，仅允许 `default` 与
  `compatibility`；监督器固定追加应用资源内唯一的最终安全 overlay，覆盖
  上游位于 profile 之后且可热更新的 home patch 层。
- auth-fence 的 HTTP、未知路径与 WebSocket upgrade 在分发前拒绝无效 token；
  正确 token 才能到达 route/upgrade handler。command guard 的保守审批规则
  与 Cordis 生命周期均通过。
- `dump-config` 基线摘要为 `cee7cd4d8c75`；带对抗 home 层和最终安全
  overlay 的 compatibility 摘要为 `9adc8eec0838`，只改安全/权限/Web Host
  与 Agent preset roster 行；default 摘要为 `d58ac9fad382`，再增加唯一
  允许的官方 brand slot 替换。compatibility 的上游 Client row 内容和顺序
  全部不变。
- `dump-config` 和 `yarn smoke:upstream` 都注入会重开上游 webserver、禁用
  auth-fence/command-guard 并请求危险权限的 home patch；最终组合仍为
  `workspace-write + ask`，真实 npm DSH 的 403/200、默认 child `SIGKILL`
  后新 token、以及产品数据 sentinel 均通过。
- `yarn package:dir` 生成未签名 `Convax.app`，再以空 PATH、隔离 HOME/CWD
  启动产物内 Node/DSH；真实 node-pty shell、只含 `standard/code` 的只读
  Agent roster、默认 profile、鉴权、UI 200、依赖 realpath 与数据 sentinel
  全部通过。
- `patches/` 和 `upstream.json#patches` 均为空，未修改上游源码。
- profile 物化从纯数据 patch 的 `insert[].name` 自动推导包链接，并要求该
  包已安装到桌面 deploy root；普通插件无需进入壳内硬编码清单。

`yarn dev` 是一条命令的显式图形开发入口；保守的
`workspace-write + ask` 权限、目录选择与 Agent UI 均来自未覆盖的上游
Client/Host row。自动门禁验证其组合与 Web 可达性，不模拟真实模型凭据或
代替用户点击发送一次付费模型请求。

## 遗留风险

- M1 只产出未签名 macOS ARM64 目录；签名、公证、自动更新和 Windows x64
  属于 M4。
- Electron `webRequest` 对原生 WebSocket header 注入需在 Electron pin
  升级时做一次图形/网络回归；Host fence 的 upgrade 门禁已有真实 server
  测试。
- DSH rc.2 的 bundle peer 元数据会让 Yarn 显示 YN0086；产品直接 peer 已
  全部满足，运行闭包由真实 Loader 与隔离产物 smoke 兜底。
