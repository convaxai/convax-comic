# BeUI 设置壳与主题呈现责任

## 背景

Default profile 已由 `@convax/project` 接管 `root`，因此官方 `ui-layout` 被禁用。
上游 theme service 只维护持久化偏好和 theme snapshot，真正写入
`body[data-ds-dark-theme]`、CSS token 与 `color-scheme` 的 presenter 原本属于
`ui-layout`。替换 root 后没有补上该呈现责任，导致 `@convax/beui` 虽然消费
`--dsw-*` token，明暗模式和 theme snapshot 中的 token override 却没有进入 DOM。
同时设置 shell 仍来自上游 primitives，与 default 的 BeUI 视觉和交互层不一致。

## 决策

1. 只在 default profile 禁用 `ui-settings-general`；compatibility 保持完整上游 Client
   roster。`@convax/ui` 占用文档化的 `sidebar.settings` single slot，并声明、渲染原有
   `settings.trigger/header/action/close/section/onboarding` 子 slot。
2. 新设置壳使用 source-owned BeUI `Button` 与 `Tabs`，但不接管 feature 事实：Models、
   Plugins、Language、Appearance、Permission、Composer 等仍由各自上游插件贡献
   `settings.section` 或 `settings.general.item`。General section 只是重新提供原扩展 seat。
3. `@convax/ui` 注册独立 `convax.settings` 中英文字典，所有 shell 可见文案和无障碍名称
   通过 DSH locale service 解析；section label 继续读取各 feature 自有 locale，并同时订阅
   slot ledger 与 locale revision。
4. 配置文件 action 仍通过 loopback-only `settings.openDocument` 和共享
   `settingsScope.describe()` mirror 工作，不暴露路径，也不复制 Host 设置事实。
5. `@convax/ui` 在自己的 Fiber 内安装与上游 `ui-layout` 等价的 theme presenter：首次读取
   `ctx.theme.getTheme()`，随后监听 `theme/change`，写入 root color-scheme、dark attribute、
   active tokens 与 theme-color meta；dispose 时只撤销自己写入的 token 和节点。
6. Presenter 只呈现 theme snapshot，不以产品品牌名义调用 `overrideTokens` 改写 palette。
   BeUI 在没有外部 brand token 时使用中性的黑/白 primary；Project 与 Canvas 读取同一
   primary。侧边栏外壳、Files、Canvases 和 sticky header 统一读取
   `--dsw-specific-sidebar-fill`，选中行使用中性 hover surface，避免列表内部出现独立色块。
7. BeUI 的 component role 先保持官网语义，再在唯一边界映射 DSH theme。官网暗色 Select
   的 trigger/content 是 base `#151515`、selected 是 muted `#1c1c1c`；不能因为 DSH manifest
   把 `bg-overlay` 描述为 popover 就直接用其暗色值 `#61666b`。Card、Popover、Secondary、
   Muted 在 BeUI 内统一由 base 与 foreground 的 3% 中性 surface 派生，focus ring 读取
   foreground alpha，primary foreground 读取 DSH 对应前景 token。
8. 全局 `BEUI_THEME_CSS` 与 `BEUI_COMPONENT_CSS` 只由 `@convax/ui` 的
   `app-ui-beui-styles` 注册一次。Project 与 Canvas 只注入领域 CSS；它们的 bundle 仍内联
   所用 primitive 实现，但不得各自再复制全局 CSS。否则不同构建时刻的三份同名 selector
   会按 Slot/DOM 顺序互相覆盖，造成源码已修正而运行时仍命中旧色值。

## 被否方案

- **只覆盖上游设置 CSS**：无法证明使用了项目组件库，仍保留两套交互语义，也解决不了
  `ui-layout` 缺失导致的 theme snapshot 未呈现。
- **让设置壳直接实现所有 feature 配置**：会复制 Locale/Theme/Model/Plugin 的事实和写路径，
  破坏“一项设置由 feature 自有”的 slot 边界。
- **重新启用官方 `ui-layout` 只取 theme presenter**：它同时占用 root 并提供同名 layout
  service，会与 Project workbench 冲突；presenter 必须跟随当前 root owner 放入产品 UI
  Fiber。
- **把 BeUI Select 直接映射到 DSH `bg-overlay` 或 `specific-menu`**：前者暗色为
  `#61666b`，后者暗色为 `#353638`，都不是官网 Select 的 base `#151515`。DSH Menu 是
  上游另一套控件的呈现语义，不能替代 BeUI 自身的 component role。
- **每个消费插件各注入一份 BeUI 全局 CSS**：局部开发只重建一个 Client 时会同时存在
  新旧 selector，最终色值取决于不可见的 DOM 顺序；这正是本次运行时与源码不一致的第二根因。
- **修改 Electron/preload**：设置和主题完全属于 Client 插件呈现，不应扩大桌面壳职责。

## 验收证据

- `@convax/ui` 测试覆盖中英文字典、完整 settings slot 拓扑、controller 生命周期、theme
  presenter 的 apply/dispose，以及全局 BeUI CSS 的单一 ownership；Project/Canvas 测试反向
  禁止再次注入全局 CSS。BeUI primitive 测试覆盖 Tabs/Button 与 Select 的 base/muted role、
  12/8px geometry、placement、height/radius pinch 和 stagger motion。
- default `dump-config` 的预期唯一组合差异是 `ui-settings-general: disabled: true`；
  compatibility dump 必须零变化，且两个 profile 均保留 `app-auth-fence`。
- 构建产物需内联各自使用的 `@convax/beui` primitive 与 Motion；全局 BeUI CSS 只出现在 UI
  Client，React 和 DSH runtime 仍从 ModuleLoader 单例获取。
