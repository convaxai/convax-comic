# 项目视频预览采用短时同源媒体租约

## 背景

目录树需要为大型本地 MP4/MOV/M4V/WebM 生成真实首帧并支持 Hover 播放。把完整视频放进 Typert unary JSON 会产生 base64 膨胀和多份内存副本；32 MiB 上限也无法覆盖实际 100 MiB 以上的交付视频。Canvas 导入仍只允许图片和文本，不能借预览扩宽持久资产边界。

## 决策

- `projectFiles/preview` 对图片、文本维持原有受限 unary 结果；对视频只返回随机 `previewId` 和同源 `/convax/project-media/<id>` 路径。
- Host 继续通过 `ctx.fs` 完成 workspace authority、相对路径、containment、symlink 和文件类型校验；随后以 `O_NOFOLLOW` 打开已解析本地路径并校验文件描述符及媒体签名。
- `app-project` 依赖既有 `webServer`，注册单一 prefix Range 路由。该 provider 是 `auth-fence`，所以无控制 token 的本机请求在路由分发前即被拒绝；token 不进入 URL、日志或持久化。
- 路由只接受 GET/HEAD 和单段 byte range，返回 `no-store`、`nosniff`、same-origin CORP；浏览器按需读取，视频字节不进入 JSON/base64。
- 最多保留 8 个租约；每次访问续期 2 分钟。Client 在缩略图提取完成、Hover 关闭、workspace 重置或卸载时主动释放；Host 超时、淘汰和插件卸载也关闭文件描述符及活动响应。
- `projectFiles/read` 不变，视频仍不能通过目录拖入成为 Canvas 节点。

## 被否方案

1. **提高 unary 上限**：129 MiB 视频会膨胀为约 172 MiB base64，并在 Host、传输和 Renderer 形成多份副本，否决。
2. **只读文件头生成首帧**：普通 MP4 的 `moov`、sample table 和关键帧位置不固定，截断 Blob 不能可靠解码，否决。
3. **把绝对路径或 `file:` URL 交给 Renderer**：绕过 workspace authority 并扩大本地文件暴露面，否决。
4. **把控制 token 放在 query**：会进入 URL 与日志，违反 token 生命周期，否决。

## 验收证据

- Project 单测覆盖视频签名、随机租约、206 Range、主动释放、Hover 关闭释放以及 video 不进入 `read` 契约。
- auth-fence 既有无 token/错误 token 403 用例继续覆盖所有 named route 的分发前认证。
- default/compatibility `dump-config` 前后无 profile 数据变化；新增的是既有 `webServer` provider 的代码级消费，不增加 provider、不改变 compatibility Client。
- preload、导航白名单、host/port、权限 profile 均无 diff。

## 遗留风险

- 文件描述符保证打开后的媒体对象稳定；祖先目录在校验与打开之间被恶意替换仍受本地可信 workspace 假设约束。若未来引入不可信同步目录，应在 `ctx.fs` 增加 no-follow ranged/open-FD 原语并移除 native opener seam。
- Canvas 图片当前仍可能只由 Renderer 临时资产表提供 URL；跨重启持久媒体需要独立产品资产仓库，不属于目录预览租约。
