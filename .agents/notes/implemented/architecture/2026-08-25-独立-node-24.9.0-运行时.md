# 独立打包 Node 24.9.0 运行时

## 背景

Electron `43.4.0` 内嵌 Node `24.18.1`，参考桌面仓库当前开启
`ELECTRON_RUN_AS_NODE`。本项目 PLAN 已固定不同的产品边界：DSH Host 是
Electron bootstrap 监督的独立子进程，并固定 Node `24.9.0`。两种 Node
的 native ABI 与发布节奏不同，不能把参考实现的进程选择当作等价细节。

## 决策

- M1 直接依赖精确的 `node-bin-darwin-arm64@24.9.0`，Electron Builder
  将其二进制和 DSH npm 运行闭包解包进应用资源。通用 `node` 安装器包
  在 Yarn 构建阶段会先解析尚未落盘的自身 `bin/node`，不可作为闭包输入。
- bootstrap 只用该二进制启动 DSH；禁止设置 `ELECTRON_RUN_AS_NODE`，也
  禁止回退到用户 PATH 中的 `node`。
- DSH 子进程与 Electron 通过受限 IPC 交换 readiness/origin；token 只走
  启动环境，不进入参数、日志或磁盘。
- Electron 与独立 Node 的 native 依赖分别按自己的 ABI 构建和验收，不能
  共享一个“恰好能加载”的产物。

## 被否方案

- **Electron `runAsNode`**：把 Host 崩溃域、Node ABI 与 Electron 升级绑
  在一起，也让“无 Electron 语义的真实上游 smoke”失去验证价值。
- **系统 Node / PATH 回退**：版本与 ABI 不可复现，且打包产物不再自包含。
- **直接执行 submodule 构建产物**：让发布依赖源码 checkout，违反固定
  npm 运行闭包的决定。

## 可证伪的验收证据

- 打包目录中的 runtime 执行 `--version` 必须精确输出 `v24.9.0`。
- 产物依赖的 realpath 全部留在应用 `Resources` 内；以空 PATH、隔离的
  HOME/工作目录启动后，真实 DSH Web smoke 通过。
- 子进程环境中不存在 `ELECTRON_RUN_AS_NODE`。
- Electron `43.4.0` 或 DSH pin 更新时，重新执行 native 闭包与打包 smoke。

## 遗留风险

Node 的架构专用 npm 包是发布输入。M1 仅验证 Darwin ARM64；其他平台没有
对应闭包时必须失败，不能静默使用系统 Node。

闭包目录与整棵进程树的后续落地见《外部 Node 闭包与进程树》；该 Note 记录
了 node-pty 对 asar 路径的约束和 parent IPC lease。
