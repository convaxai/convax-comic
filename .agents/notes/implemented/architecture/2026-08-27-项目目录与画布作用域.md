# 项目目录、实时文件树与 Canvas 作用域

## 背景

Convax 的默认工作台此前把 Canvas 固定绑定到
`workspace:default/project:default`，左侧“Files”也只是 Canvas 图片节点投影，
不是 DSH 已绑定项目的文件目录。DSH 本身已经持有多 Workspace、Session 与 cwd
关系；Electron 仍必须保持无项目业务逻辑，浏览器也不能获得或信任 Host 绝对路径。

同时，文件树不能靠用户手动刷新。VS Code Explorer 的关键不是“每次事件全量递归
扫描”，而是文件 provider 的权威读取、按已读目录布置的一层 watcher 失效提示、事件
聚合、展开目录懒解析、可见行虚拟化和丢事件后的 reset/refetch。

## 决策

1. 新增 dual Host/Client physical plugin `@convax/project`，由 default profile 以
   `app-project` 挂载。Electron bootstrap、preload 和控制面没有项目业务改动；
   compatibility 不挂载任何新 Client 呈现。
2. C1 的 Comic Project 直接投影 DSH Workspace。活动 scope 为
   `{ workspaceId: <DSH Workspace UUID>, projectId: 'project:root' }`。顶部切换器读取
   官方 `ctx.workspaces.list`，通过 `connectWorkspace(workspaceId)` 与
   `ctx.sessions.open(sessionId)` 导航，使当前 Agent Session cwd 与可见项目一致。
3. Project Client 拥有通用 workbench `root`、`sidebar.workspaces`、`layout` 与
   `comicProject` provider；Canvas 不再拥有壳，只向 `workbench.center` 和
   `project.canvases` slot 贡献领域 UI。Workspace 变化撤销并重新提供
   `comicProject`，依靠 Cordis required-service lifecycle 完整 dispose/restart
   Canvas，而不是再建全局 ActiveSet 或 broker。
4. Project Host 只接受 Workspace ID、租约 ID 和受限相对目录。它从
   `workspaceRegistry` 取规范根，经 `ctx.fs.resolve`、`contains`、`lstat` 与
   `listDir` 权威读取一个目录层级；返回 JSON-safe 相对 DTO，不返回绝对路径、
   `FsTarget` 或活对象。symlink 不可展开，默认忽略 `.git`、`node_modules`、
   构建与缓存树。
5. Chokidar 5 使用 `followSymlinks:false`，但不在项目打开时递归遍历整棵目录：Host
   只为项目根和 Client 已实际加载的目录各建一个 `depth:0` 一层 watcher，事件仅作失效
   提示。Host 对事件做批量、单调 revision、有限 ring 与 reset 语义；Client 长轮询后
   只重读已展开/可见分支。序列缺口、overflow、watcher 错误和页面恢复焦点都触发
   reset/refetch。`fs/observed` 的 write/edit 事件只用于加速同一失效路径。
6. Canvas Client 的单项目 primitive 在 `PROJECT_NOT_FOUND` 时可显式初始化根项目。
   Host Agent 工具不读取浏览器选择，而在每次 execute 时从
   `exec.agent.session.header.cwd` 经 `workspaceRegistry.resolveByPath` 解析 Workspace
   scope 并惰性初始化，以避免旧会话或后台 Agent 改写新切到的项目。
7. 现有 Canvas SQLite 保持一个产品自有物理库；其 `(workspaceId, projectId)` 复合
   主键已经提供逻辑项目隔离，本次不引入无必要的物理分库或破坏性迁移。

## 被否方案与理由

- **把文件树与切换逻辑写入 Electron**：违反“桌面即插件”和恒定插件接入成本，
  也会扩大 preload/IPC 攻击面。
- **Canvas 继续拥有 root/sidebar**：把通用项目导航耦合到领域编辑器，后续媒体库、
  导出器等无法独立贡献；改为 Project 声明 slot、Canvas 消费。
- **每次 watcher 事件全量递归扫描**：大型仓库成本随项目总规模增长，事件风暴会
  放大；改为事件聚合和展开分支的一层权威重读。
- **把 watcher 结果当权威状态**：原生队列可能溢出、合并或丢失；必须保留
  revision/reset 和 `ctx.fs.listDir` 重读。
- **首版采用 `@parcel/watcher`**：当前 Yarn 禁止安装脚本且桌面有独立 Node 运行时，
  native binary 增加 ABI/打包矩阵；Chokidar 5 是 Node 22.19+/24+/26 可运行的纯 JS
  方案。只有真实性能基准和打包探针证明必要时再切换 provider。
- **Canvas Agent 工具跟随浏览器全局 selection**：并发或后台 Session 会跨项目写；
  Session cwd 才是每次调用的隔离路由键。
- **本次新增稳定 product project catalog**：DSH Workspace 已满足绑定与切换主路径，
  Canvas 复合键也可直接隔离；目录删除后重注册的 rebind/迁移需要用户可见策略，
  不能在 C1 静默别名。

## 可证伪的验收证据

- profile gate 与 before/after `dump-config` 证明仅 default 新增 `app-project`，
  compatibility Client roster 零变化且 `auth-fence` 保留。
- Host 测试覆盖相对路径语法、containment、symlink、忽略规则、lazy list、写入失效、
  租约关闭与 watcher disposer；Client 测试覆盖项目/session 选择、root slot、scope/layout
  provider 与完整卸载。
- Canvas 测试证明缺项目初始化、project-scoped slot contribution、每次 Agent tool
  execution 重新解析 scope、provider 卸载/恢复与旧 waiter 被取消。
- `yarn build && yarn typecheck && yarn test && yarn check:profiles &&
  yarn check:dump-config` 全绿；打包门禁确认新插件及 Chokidar 进入运行闭包。

## 2026-08-31 项目切换一致性修复

- Cordis 4.0.1 的 `ctx.set()` 只替换 service 值，不触发 required-service Fiber
  重启；因此活动 Workspace 变化必须串行撤销旧 `comicProject` provider，等待
  Canvas 完整 cleanup 后重新 provide。scope 订阅与 provider 同属
  `remote.projectFiles` injected child，Remote 重连或 HMR 时不会遗留首个 runtime。
- 显式项目导航采用 last-intent-wins token，并在 `connectWorkspace()` 完成前先投影
  用户选择；逆序完成的旧请求不得再次 `sessions.open()`。添加项目复用同一条路径，
  因而文件树、Session 与 Canvas scope 只收敛到最后一次用户意图。
- 自动首选等待 DSH Workspace/Session 双 baseline ready，避免先打开列表首项再切到
  恢复 Session；已存在但未归属 Workspace 的 current Session 不再误配 recent 项目；
  同一路径并发目录读取以 request generation 丢弃晚到旧响应。
- 回归测试覆盖 phased baseline、逆序快速切换、新增项目、目录响应逆序以及
  `comicProject` provider 的 dispose/re-provide 生命周期。

## 项目切换性能修复

- 原实现的 `projectFiles.open` 必须等待 Chokidar 对整个 Workspace 递归建表并触发
  `ready`，切换时又先等待旧递归 watcher 全量关闭。即使文件全在本地，耗时和文件数、
  目录数及系统 watcher 限额相关，而不是只和根目录展示的 250 项相关。
- Host 改为只在 `open` 时等待根目录 `depth:0` watcher；Client 首次读取某个展开目录时，
  Host 先为该目录建立并等待独立的一层 watcher，再执行权威 `listDir`，从而保留
  “先监听、后快照”的不丢窗口语义，但项目切换成本不再随未展开子树规模增长。
- `listDir` 仍需用 `lstat` 区分 symlink；原先逐项串行读取会把本地元数据延迟累加，
  现在使用上限 32 的并发读取。响应上限、忽略规则、排序、symlink 禁止展开与 JSON
  contract 均不变。
- 当前 checkout 基准中，同一根目录 Chokidar `ready` 从递归监听约 43 ms 降为一层监听
  约 2 ms；更大的素材库收益取决于未展开目录规模。回归测试锁定按需 watcher 生命周期
  和并行元数据读取。
- Canvas 的 `getProject` 响应已经包含全部 Canvas 文档；原启动流程仍紧接着调用
  `getDocument`，导致同一 SQLite `project_json` 在 UI 出现前被再次全量读取、校验和 clone。
  `CanvasProjectSync` 现在把权威 project 响应中的目标文档作为 `CanvasClientService` 初始
  snapshot；service 仍立即启动 revision waiter 校验后续变化，但项目启动和 Canvas 切换
  不再被第二次全项目读取阻塞。

## 2026-09-01 Files→Canvas 安全拖拽

- Project 文件行使用独立 MIME `application/vnd.convax.project-file.v1+json`，拖拽数据
  严格只有 `{workspaceId, path}`。目录、symlink 与 other 条目不可拖；名称、大小、
  MIME、租约、绝对路径和 `FsTarget` 都不进入 DataTransfer。
- Canvas 先校验拖拽 Workspace 与当前 `comicProject` scope 一致，再通过 scope 的
  cancellable `readFile(path, signal)` 调用 Project Typert Remote。Host 独立重做
  Workspace 查找、4096 字符相对路径、逐段 symlink、`resolve/contains`、regular-file
  与大小校验；最终读取走 `ctx.fs.readBytes` 的硬上限，不新增 Electron/preload 文件 API。
- 当前 C1 只导入严格 UTF-8 文本（成为 `comic.note@1`）和通过扩展名+magic byte 双重
  校验的 PNG/JPEG/GIF/WebP（成为 `comic.image@1`）。文本上限 100,000 bytes/chars，
  图片跨 Remote 上限 10 MiB；二进制、SVG、未知类型与 NUL 文本明确失败。
- 目录树图片沿用现有临时媒体语义：base64 只用于本次有界 Host→Client 传输，随后转换
  为 session-only `File`/object URL；Canvas V2 仅持久化临时 asset ID，bytes、blob URL
  和项目路径都不落库。失去引用、切换 project 或卸载时释放 URL；持久资产仍留给 C2。
- Canvas workspace 拥有 import AbortController；project scope 切换/卸载会取消在途读取，
  晚到结果不得写入已经 dispose 或已切换 active canvas 的 workspace。

## 遗留风险

- `ctx.fs.listDir` 会完整物化一个目录层级；当前条目上限限制响应和渲染，不是真正的
  scan-time 分页。超宽单层目录需要上游 iterator API 才能从根因限制内存。
- 同一路径删除 Workspace 后重新注册会获得新 UUID，旧 Canvas 成为 orphan。本次不
  自动删除或迁移；C2 需要产品 project catalog、显式 rebind/copy 以及可回滚迁移。
- 网络盘、极端事件风暴和平台 watcher 差异仍需真实仓库基准；reset/refetch 保证正确性，
  但不承诺所有文件系统上的最低延迟。
