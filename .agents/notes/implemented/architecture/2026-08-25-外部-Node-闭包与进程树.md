# 外部 Node 闭包与进程树

## 背景

这是对《独立打包 Node 24.9.0 运行时》的落地补充。把整套生产依赖放在
`app.asar.unpacked` 虽能让外部 Node 读取，但 `node-pty` 会把路径中的
`app.asar` 替换为 `app.asar.unpacked`；已经处在该目录时会得到
`app.asar.unpacked.unpacked`，真实 Agent shell 因找不到 `spawn-helper` 失败。
同时，Electron 只结束直属 DSH 进程不足以拥有 PTY/Agent 孙进程的生命周期。

## 决策

- M1 关闭 asar，把 Electron 与独立 Node 共用的生产闭包放在普通
  `Resources/app`；发布门禁反向禁止重新出现 `app.asar`。
- 打包 smoke 不只探测 HTTP：用产物内 Node/native addon 真正创建 PTY，运行
  `/bin/sh` 并校验输出。
- macOS/Linux 下 DSH 作为独立 process group leader 启动；停止、超时、启动
  失败和 crash close 都向整组发信号，正常退出给上游 5 秒清理边界之外的
  7 秒 grace。
- 独立 Node 在加载 DSH 前先 `--require parent-guard.cjs`。Electron 若被强杀，
  IPC lease 断开会立刻向 DSH 自身发 SIGTERM，进入上游完整 Cordis disposal；
  desktop Host 插件挂载后保留同一防线。

## 被否方案

- **补一个 `.unpacked.unpacked` symlink/复制 helper**：绑定 node-pty 的内部
  字符串替换实现，签名与升级都脆弱。
- **继续只杀直属 child**：DSH 先退出或 Electron 崩溃时孙进程可能跨代存活。
- **缩短上游 shutdown grace**：会截断 session/telemetry/PTY 的正常 disposal。

## 可证伪的验收证据

- 打包门禁确认 `Resources/app` 存在且 `Resources/app.asar` 不存在。
- 空 PATH、隔离 HOME/CWD 下，产物 Node 精确为 `v24.9.0`，node-pty shell
  输出 `convax-pty-ok`，随后真实 DSH profile、UI 与鉴权均通过。
- supervisor 单测确认 child 以独立 process group 启动，并覆盖 grace 后
  SIGKILL、崩溃重启与退出回收。

## 遗留风险

M1 目录产物未签名，普通资源目录的完整性在 M4 由签名/公证闭合。Windows
x64 不能复用 POSIX process group，进入该平台前必须采用 Job Object 或等价
的整树回收机制并新增真实 PTY 产物测试。
