# Canvas V2 扩展契约与 Host/Client/Builtins 边界

## 背景

C1 的 V1 schema 以固定 `kind` union、node/edge 数组和整文档 replace 验证了
React Flow 工作台，但它把所有节点类型、Host 验证、Client 呈现和同步策略绑定
在一个实现里。继续增加漫画节点会要求核心包反复改 union，第三方插件也无法在
不接管 Canvas 的前提下贡献节点。

远程 `convax-next` 已证明 `type + kindVersion + JSON data`、Host node registry、
Client renderer registry、受限 leaf Patch 和 bounded revision waiter 的基本方向。
Comic 不能照搬其无 edge、单 Canvas/DSH workspace 假设，必须保留当前 edges、
多 Canvas project、工作台和工具能力。

## 决策

- 新增 contract-only `@convax/canvas-api`。契约不依赖 React Flow runtime，所有
  Host/Remote 持久数据必须是可验证、可克隆的 JSON。
- 权威文档直接采用 `schemaVersion: 2`：node 使用
  `id/type/kindVersion/position/zIndex/style/data`，node 与 edge 均为 ID map；
  edge 保留 source/target/handles 和可扩展 JSON data；project 保留
  activeCanvasId 与多个 Canvas ID map。
- 不为现有开发期 V1 数据增加自动迁移、双写或运行时 fallback。当前没有稳定
  用户历史负担；不符合 V2 的已有 CanvasStore row 明确失败，清理或显式导入由
  开发/产品流程负责。
- 普通写入使用受限 Patch：node/edge 只允许 map entry add/remove；metadata、
  viewport、position、style 和 plugin-owned data 只允许替换既有 leaf；禁止修改
  identity、revision、aggregate、prototype 相关 segment。整批在 clone 上应用，
  失败携带 operation index 且不得产生部分状态。
- 删除 node 时必须在同一 batch 删除所有 incident edges，否则最终图校验拒绝；
  node 创建后普通 Patch 不允许改变 type/kindVersion，类型升级属于显式 migration。
- Host 与 Client registry 均以 `(type, kindVersion)` 注册和精确 resolve，同一
  type 的多个历史版本可并存。未知已有节点允许无损读取，并仅开放核心
  geometry/style、连线和删除；未知新节点不得创建或复制。
- 首批 builtins 物理拆为 `@convax/canvas-builtins`：Host 贡献
  `comic.note@1`、`comic.image@1`、`comic.sequence@1`，Client 对称贡献 renderer；
  核心 Canvas wrapper 继续拥有 selection、handles、resize 和标题 chrome。
- Host commit 保持 serialized candidate -> CanvasStore CAS -> publish。文档 revision
  在持久成功后推进，committed event 只在事务落地后发出且逐 listener 隔离异常。
  Agent active-canvas mutation 同时 CAS project revision、activeCanvasId 与 document
  revision；create-and-activate 只提交一次。
- waiter 上限 30 秒，先订阅再读取以关闭 race，Store 慢读也必须与绝对 deadline/
  abort 竞速；timeout 不返回大文档，删除返回 deleted，Host dispose 取消 waiter。
  Client 对一个打开 Canvas 只保留一个 waiter，并对瞬态失败有限指数退避。
- `@convax/canvas-api`、`@convax/canvas` 与 `@convax/canvas-builtins` 已形成物理
  Contract/Core/Builtins 边界；`canvasStore` 另由 SQLite provider 显式提供，
  composition 的 required inject 负责缺失、卸载与恢复。Host 与 Client 分别注册同一组
  `canvasV2/*` strict Typert descriptors；Host contribution 必须先于 Remote receiver 发布，
  不能依赖未标注方法的 SRC fallback。Remote receiver 属性不得使用无法穿过 Cordis Service
  proxy 的 JavaScript private field。

## 被否方案

### 继续扩大固定 kind union

每个领域节点都要求改核心 schema、工具和 UI，无法让插件独立演进；否决。

### 继续整文档 replace

并发 leaf 修改互相覆盖，失败恢复和外部 committed event 难以判定；只保留为明确
导入/导出边界，不作为编辑同步协议。

### 直接复制 Next 并删除 edges/multi-canvas

会回退 Comic 已有连接、项目浏览器和工作台能力；否决。Comic V2 在 Next contract
上增加 edge map 和 project authority。

### 在 Contract/registry 稳定前一次性拆动态 package/profile row

会同时改变 schema、Remote、ModuleLoader、Client bundle 和组合拓扑，故障面过大。
实际按 Contract → Host/Client → physical builtins → profile 的顺序落地，每一步先以
headless 生命周期测试验收；最终组合仍保持普通插件的恒定挂载成本。

## 可证伪验收

- schema：JSON-only、ID map、edge 引用、危险 key、runtime field、大小/数量上限；
- Patch：leaf 白名单、RFC6901、prototype pollution、atomicity、operation index、
  node+edge 原子删除；
- Host registry：duplicate、kindVersion/data、unknown existing、idempotent dispose；
- Client registry：exact resolve、unknown fallback、snapshot/subscribe、生命周期；
- Host：并发 leaf mutation、CAS/IO 失败不发布、revision 持久、wait race/timeout/
  deleted/cancel；
- Client：单 waiter、revision gap、local optimistic 去重、旧 action 失效；
- 回归：edges、多 Canvas、Space pan、resize、tidy、undo/redo、root/sidebar/
  workbench.agent、八个 Agent tool names；
- 外部 fixture 只依赖 `@convax/canvas-api` 即可分别注册 Host 类型和 Client
  renderer，并在贡献插件卸载后无残留；
- compatibility 的 Client dump 无新增行；安全 overlay 和产品目录边界不变；
- upstream 与 packaged smoke 必须通过真实 `/api/canvasV2/getProject` Connection envelope，
  同时覆盖 Host strict descriptor 注册、Gateway route、Cordis Service proxy receiver 与
  V2 result validation，不能只检查 Host 启动或 fake Remote。

## 遗留风险

- 图片持久资产仍未实现，V2 只定义稳定 opaque asset reference；临时 File/object URL
  生命周期已迁移，但重启后的资产解析属于 C2。
- 类型 migration API 尚未定义；多个 kindVersion 可并存，存量旧版本在对应插件未挂载
  时按 unknown read-only 处理，禁止隐式升级。
- 多进程共享同一 SQLite 文件仍依赖 SQLite CAS；当前 Host 内 mutation 全局串行，跨 Host
  竞争统一映射 `REVISION_CONFLICT`，但没有协作合并协议。
